Who gets the CPU next?

Hundreds of times a second, an operating system makes one greedy choice: which ready process runs now. This lab implements ten scheduling strategies in modern C++, runs that same engine in your browser, and shows every decision, tick by tick, along with what each one costs in waiting time, responsiveness and fairness.

What a scheduler is judged on

There is no single best algorithm, only trade-offs between these numbers. Every view below measures all of them.

Waiting time

Time spent ready but not running. The classic target — shortest-job strategies minimise it.

turnaround − burst

Turnaround

Arrival to completion. What a batch user experiences end-to-end.

finish − arrival

Response time

Arrival to first run. What makes an interactive system feel fast — Round Robin and Feedback excel.

first run − arrival

Fairness

Jain’s index over normalised turnaround. 1.0 means every process was slowed down equally.

(Σx)² / (n·Σx²)

      Scheduling engine

      Performance benchmarking

      Waiting, turnaround and response time, CPU utilisation, context switches and fairness across thousands of seeded workloads — up to ~30% less average waiting than FCFS.

      Reproduce the numbers →
      04

      Modular implementation

      Each algorithm is one class behind a Scheduler interface, registered in an STL unordered_map; ready queues use STL queue (Round Robin) and priority_queue heaps (SJF, SRT, Feedback). Adding an algorithm is one class and one line.

      Adding an algorithm

      // src/algorithms/fcfs.cpp
class FirstComeFirstServed final : public Scheduler {
  AlgorithmInfo info() const override;
  void schedule(SimulationContext& ctx, int) const override {
    for (int p : ctx.arrivalOrder()) {
      ctx.decide(time, p, "Earliest arrival still waiting");
      // run p to completion, then ctx.complete(p, time)
    }
  }
};
